# Cross-Site Scripting (XSS) Attack Detection using Machine Learning

A machine-learning based security project that classifies input text as **SAFE** or **XSS ATTACK**, with **SHA-256 cryptographic fingerprinting** for the analyzed input.

## Case Study Objective

The project studies Cross-Site Scripting (XSS), a web security attack in which malicious scripts or HTML are injected into web applications.

The ML component learns patterns from a Kaggle XSS dataset and predicts whether a new input is malicious. A SHA-256 hash is also generated for every analyzed input as the cryptographic component of the case study.

## Project Flow

```
Kaggle XSS Dataset
        ↓
Data Cleaning
        ↓
Train/Test Split
        ↓
Character-level TF-IDF
        ↓
Logistic Regression
        ↓
SAFE / XSS ATTACK
        ↓
Web Application
        ↓
SHA-256 Cryptographic Fingerprint
```

For a user-submitted input, the ML detector and SHA-256 operation are independent:

```
User Input
    ├──→ Character TF-IDF → Logistic Regression → XSS / SAFE
    │
    └──→ SHA-256 → 64-character hexadecimal fingerprint
```

**Important:** SHA-256 is not used as an ML feature and does not itself detect XSS. It is used as a cryptographic fingerprint/integrity mechanism. The ML model performs the attack classification.

## Dataset

This project uses the Kaggle **Cross-Site Scripting (XSS) Dataset for Deep Learning**. The commonly used version contains about 13,686 samples with HTML/JavaScript text and binary labels.

After cleaning empty rows and duplicate records, our working dataset contained **10,854 usable samples**.

The dataset contains:
- `Sentence` — input text
- `Label` — safe or XSS classification

## Machine Learning Pipeline

We use:

- Character-level TF-IDF
- Character n-grams from 3 to 5
- Logistic Regression
- Stratified 80/20 train-test split

## Cryptographic Component — SHA-256

SHA-256 (Secure Hash Algorithm 256-bit) is a cryptographic hash function.

For every submitted input, the application calculates:

```
SHA-256(input)
```

The output is a fixed **256-bit (64 hexadecimal character)** digest.

Example:

```
Input:
<script>alert('XSS')</script>

SHA-256:
[generated by the application]
```

The same input produces the same hash, while a change to the input produces a different hash with very high probability. This gives each analyzed input a cryptographic fingerprint.

### Why SHA-256 is included

The project is primarily an ML-based XSS detector, but the case study also requires a cryptographic component. SHA-256 provides that component without interfering with the ML pipeline.

We deliberately do **not** hash the input before TF-IDF because the ML model needs the original character patterns to detect XSS.

## Web Application

The application accepts user input and returns:

- XSS ATTACK or SAFE
- Detection confidence
- Detector used
- SHA-256 cryptographic fingerprint

## Security Note

This is a machine-learning case-study project and should not be treated as a complete Web Application Firewall or a guarantee against every possible XSS variant.

SHA-256 is used here for cryptographic fingerprinting. It does not provide encryption, and it does not replace proper XSS defenses such as input validation, output encoding, Content Security Policy, and secure application design.
